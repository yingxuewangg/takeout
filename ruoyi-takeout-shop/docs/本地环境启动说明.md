# 本地环境启动说明（MySQL + Redis + RocketMQ）

本项目本地依赖通过 Docker Compose 一键拉起，**MySQL/Redis/RocketMQ 均运行在 Docker 容器内，不会安装到 Windows 本机**；不想要时随时可彻底清除。

## 1. 前置条件

- 已安装并启动 Docker Desktop（右下角鲸鱼图标常亮，WSL2 后端默认即可）。

## 2. 一键启动

```bash
cd ruoyi-takeout-shop
docker compose up -d
```

首次启动会自动拉取镜像（数分钟），MySQL 首次初始化时自动建库 `takeout` 并按顺序执行建表脚本：

1. `sql/ry_20260417.sql` —— 若依系统表
2. `sql/quartz.sql` —— 定时任务表
3. `sql/ruoyi-takeout.sql` —— 业务 biz_ 表（13 张）+ 初始数据

## 3. 验证环境

```bash
docker compose ps                 # 各容器 Up / healthy
docker compose logs mysql         # 看到进不到容器问题的排查入口
```

## 4. 服务地址（后端 application.yml 已按此配置）

| 服务 | 地址 | 容器内 | 说明 |
|---|---|---|---|
| MySQL | localhost:3306 | 3306 | 库 takeout，账号 root/root |
| Redis | localhost:6379 | 6379 | 无密码 |
| RocketMQ NameServer | localhost:9876 | 9876 | broker 自动建 topic |
| RocketMQ broker | localhost:20911 | 20911 | 客户端经 NameServer 发现（Windows 保留端口区间覆盖默认的 10909-10952，故改用 20911，见 docker/rocketmq/broker.conf） |
| RocketMQ 控制台（可选） | http://localhost:8180 | 8080 | 需用 dashboard profile 启动 |

## 5. 可选：RocketMQ 控制台

```bash
docker compose --profile dashboard up -d
```

访问 http://localhost:8180 可查看 topic、消息轨迹。

## 6. 常用运维

```bash
docker compose stop               # 停止（保留容器）
docker compose start              # 再次启动
docker compose down               # 删除容器，数据卷保留
docker compose down -v            # 连数据卷一起删除（下次启动重新建表，相当于全新环境）
```

## 7. 常见问题

- **3306/6379 端口被占用**：本机若装有原生 MySQL/Redis 并在运行，先停掉它们，或修改 docker-compose.yml 左侧映射端口并同步修改 application.yml。
- **RocketMQ 控制台/发送消息连不上 broker**：确认 `docker/rocketmq/broker.conf` 中 `brokerIP1=127.0.0.1` 未改动。
- **Docker Desktop 启动后容器没起来**：执行 `docker compose up -d` 前，确认 Docker Desktop 已完全启动（不是"starting"状态）。
- **想重建业务表**：`docker compose down -v && docker compose up -d`（会清掉全部数据，包括若依系统表数据）。

## 8. 中文乱码说明（已内置修复）

MySQL 容器内无 LANG 时，mysql 客户端会话默认 latin1，初始化 SQL 中的中文会被双重编码入库。本项目已在 4 个初始化 SQL 文件头部统一加了 `SET NAMES utf8mb4;`（确定性修复），无需额外操作。

两点注意：
- 以后新增初始化 SQL（挂载到 `/docker-entrypoint-initdb.d/`），文件头同样要加 `SET NAMES utf8mb4;`；
- 手动向容器导中文数据时：`docker exec -i takeout-mysql mysql -uroot -proot --default-character-set=utf8mb4 takeout < xx.sql`。
