# 阿婆干饭社 · 生产部署手册（三期 T28）

> 适用范围：后端 `ruoyi-takeout-shop`（RuoYi-Vue 多模块，Spring Boot）、商家端 `ruoyi-takeout-shop-web`（Vue3 + Element Plus）、用户端小程序 `takeout-uniapp`（uniapp + Vue3）。
> 本手册只写配置与步骤，不含任何真实密钥；所有密钥一律通过环境变量或部署机本地文件注入（见第 5 节）。
> 示例域名统一用 `api.example.com`（后端/小程序接口）与 `admin.example.com`（商家端），部署时全局替换为实际域名。

---

## 0. 架构与端口总览

| 组件 | 端口 | 暴露范围 | 说明 |
| --- | --- | --- | --- |
| Nginx | 80 / 443 | 公网 | 唯一对外入口：反代后端、托管商家端 dist、HTTPS |
| 后端 ruoyi-admin.jar | 4121 | 仅本机（127.0.0.1） | `server.port=4121`，`context-path=/` |
| MySQL 8 | 3306 | 仅内网/本机 | 库名 `takeout` |
| Redis（redis-stack） | 6379 | 仅内网/本机 | 缓存/登录态/防重锁 |
| RocketMQ namesrv | 宿主机 19876 → 容器 9876 | 仅本机 | `rocketmq.name-server: localhost:19876`（9876 落在 Windows 保留段才改的映射，Linux 生产可直接 9876:9876） |
| RocketMQ broker | 20909/20911/20913 | 仅内网 | `broker.conf` 需设 `brokerIP1=<服务器内网IP>` |
| WebSocket | 经 Nginx wss | 公网 | `/websocket/order`（商家端新订单提醒） |

**防火墙/安全组放行原则**：公网只开 80、443（以及必要的 SSH 管理端口）；3306、6379、19876、20909-20913、4121 一律不对公网开放，云安全组与系统防火墙双份确认。

## 1. 域名解析与 ICP 备案清单

微信小程序 request 合法域名**强制要求 HTTPS + ICP 备案**，先办备案再上线。

| 事项 | 说明 | 状态勾选 |
| --- | --- | --- |
| 购买域名 | 建议主域 `example.com`，解析 `api` / `admin` 两条 A 记录到服务器公网 IP | ☐ |
| ICP 备案 | 国内服务器（阿里云/腾讯云等）必须完成主体+网站备案，通常 1~3 周 | ☐ |
| SSL 证书 | Let's Encrypt 免费证书即可（`certbot` 自动续期），或云厂商免费 DV 证书 | ☐ |
| 微信公众平台 | 注册/绑定小程序，记下 `AppID`、`AppSecret` | ☐ |
| 微信商户平台 | 申请商户号，开通 JSAPI 支付，记下 `mchId`、商户 API 证书序列号、APIv3 密钥，下载商户私钥 `apiclient_key.pem` | ☐ |
| 商户号 ↔ 小程序绑定 | 商户平台"AppID 账号管理"里关联小程序 AppID（JSAPI 支付必须） | ☐ |

## 2. 中间件部署（docker compose）

服务器安装 Docker 与 compose 插件后，使用仓库自带 `ruoyi-takeout-shop/docker-compose.yml`（MySQL8 + redis-stack + RocketMQ 5.3.1 namesrv/broker/dashboard）：

```bash
cd ruoyi-takeout-shop
docker compose up -d
docker compose ps          # 全部 healthy/up
```

生产调整两点：

1. **数据库初始化**：按顺序导入 `ruoyi-takeout-shop/sql/ruoyi-takeout.sql` → `ruoyi-takeout-job.sql`（全量），再依次执行根目录 `sql/` 下增量脚本（t18…t25，文件头部注释有顺序说明）。
2. **RocketMQ broker**：编辑 broker 配置把 `brokerIP1` 改为服务器内网 IP（容器内默认 IP 外部连不上）；若在 Linux 上可直接用 `9876:9876` 映射并同步改后端 `rocketmq.name-server`。

> 数据库/Redis/RocketMQ 口令请在 compose 覆盖文件（`docker-compose.override.yml`，不入仓）中修改默认密码，不要用示例值上生产。

## 3. 后端部署

### 3.1 构建

构建机（或 CI）执行：

```bash
cd ruoyi-takeout-shop
mvn -pl ruoyi-admin -am package -DskipTests
# 产物：ruoyi-admin/target/ruoyi-admin.jar
```

上传 `ruoyi-admin.jar` 到服务器 `/opt/apos/`，目录规划：

```
/opt/apos/
├── ruoyi-admin.jar
├── application-local.yml      # 生产本地配置（第 5 节模板；权限 600）
└── cert/
    └── apiclient_key.pem      # 微信商户 API 私钥（权限 600，绝不入 git）
```

### 3.2 方式一：systemd（推荐）

`/etc/systemd/system/apos.service`：

```ini
[Unit]
Description=ApoGanfanShe takeout backend (RuoYi)
After=network.target docker.service

[Service]
Type=simple
User=ruoyi
WorkingDirectory=/opt/apos
# 密钥走 EnvironmentFile，不写进单元文件（该文件权限 600）
EnvironmentFile=/opt/apos/apos.env
ExecStart=/usr/bin/java -Xms512m -Xmx1024m -jar /opt/apos/ruoyi-admin.jar
SuccessExitStatus=143
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

`/opt/apos/apos.env`（权限 `chmod 600`，内容见第 5 节环境变量表）。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now apos
sudo systemctl status apos
curl -s http://127.0.0.1:4121/captchaImage   # 本机健康检查
```

### 3.3 方式二：Docker

```bash
docker run -d --name apos-backend \
  --restart=unless-stopped \
  -p 127.0.0.1:4121:4121 \
  -v /opt/apos/application-local.yml:/application-local.yml:ro \
  -v /opt/apos/cert/apiclient_key.pem:/opt/apos/cert/apiclient_key.pem:ro \
  -v /opt/apos/apos.env:/apos.env:ro \
  -v /opt/apos/logs:/home/ruoyi/logs \
  --env-file /opt/apos/apos.env \
  eclipse-temurin:17-jre \
  java -jar /ruoyi-admin.jar
```

> 先把 jar 一并挂载或打进镜像；示例给出挂载写法。注意只映射到 `127.0.0.1`，由 Nginx 对外。

## 4. Nginx 反向代理 + HTTPS

`/etc/nginx/conf.d/apos.conf`：

```nginx
# ---------- 后端 API（小程序 + 商家端接口） ----------
server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;

    # 微信回调 /api/pay/wechat/** 与普通接口同源反代
    location / {
        proxy_pass http://127.0.0.1:4121;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }

    # 商家端 WebSocket（新订单提醒）
    location /websocket/order {
        proxy_pass http://127.0.0.1:4121;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
    }
}

# ---------- 商家端静态资源 ----------
server {
    listen 443 ssl http2;
    server_name admin.example.com;

    ssl_certificate     /etc/letsencrypt/live/admin.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/admin.example.com/privkey.pem;

    root /opt/apos/web-dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # SPA 路由兜底
    }

    # 商家端所有接口走 /prod-api 前缀转发到后端
    location /prod-api/ {
        proxy_pass http://127.0.0.1:4121/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto https;
    }
}

# 80 跳 443
server {
    listen 80;
    server_name api.example.com admin.example.com;
    return 301 https://$host$request_uri;
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 5. 生产配置（密钥注入规范）

原则：**仓库里只有 `${ENV_VAR:}` 占位（application.yml 已就位）**；真实值只存在于部署机的两个不入仓文件里——`apos.env`（环境变量，放密钥）与 `application-local.yml`（放结构化连接配置）。后端通过 `spring.config.import: optional:...application-local.yml` 自动加载 jar 旁边的该文件。

### 5.1 /opt/apos/apos.env（环境变量模板）

```bash
# ===== 微信小程序（公众平台）=====
TAKEOUT_WX_APPID=wx你的小程序appid
TAKEOUT_WX_SECRET=你的小程序secret

# ===== 微信支付（商户平台，APIv3）=====
TAKEOUT_WXPAY_APPID=wx你的小程序appid          # 与上面一致
TAKEOUT_WXPAY_MCH_ID=你的商户号
TAKEOUT_WXPAY_MCH_SERIAL_NO=商户API证书序列号
TAKEOUT_WXPAY_API_V3_KEY=商户APIv3密钥(32位)
TAKEOUT_WXPAY_PRIVATE_KEY_PATH=/opt/apos/cert/apiclient_key.pem
TAKEOUT_WXPAY_NOTIFY_URL=https://api.example.com/api/pay/wechat/notify
TAKEOUT_WXPAY_REFUND_NOTIFY_URL=https://api.example.com/api/pay/wechat/refund/notify

# ===== 数据库口令（连接串在 application-local.yml）=====
SPRING_DATASOURCE_DRUID_MASTER_PASSWORD=生产MySQL口令
SPRING_DATASOURCE_DRUID_MASTER_USERNAME=takeout
SPRING_DATASOURCE_DRUID_MASTER_URL=jdbc:mysql://localhost:3306/takeout?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8

# 若依后台 token 密钥（>=32 位随机串：openssl rand -base64 48）
TOKEN_SECRET=生产环境随机长密钥
```

> Spring Boot 原生支持把 `spring.datasource.druid.master.url` 映射为环境变量 `SPRING_DATASOURCE_DRUID_MASTER_URL`，因此数据库连接也可全部走 env，无需改 application-local.yml。

### 5.2 /opt/apos/application-local.yml（可选补充模板）

不想用环境变量的项放这里（同样不入仓）：

```yaml
# 生产本地配置（部署机专用，权限 600；由 spring.config.import 自动加载）
spring:
  datasource:
    druid:
      master:
        url: jdbc:mysql://localhost:3306/takeout?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
        username: takeout
        password: 生产MySQL口令
      statViewServlet:
        enabled: false          # 关闭 Druid 控制台（或改强密码+白名单）
  data:
    redis:
      host: localhost
      port: 6379
      password: 生产Redis口令

rocketmq:
  name-server: localhost:9876

takeout:
  wx:
    mock-enabled: false         # 登录走真实 code2session
  file:
    base-url: https://api.example.com   # 图片/文件访问对外域名

payment:
  mock:
    enabled: false              # 切到真实微信支付实现（T22 双实现装配开关）

springdoc:
  api-docs:
    enabled: false              # 生产关闭 Swagger
  swagger-ui:
    enabled: false
```

### 5.3 密钥安全守则

- `application-local.yml`、`apos.env`、`*.p12`、`*.pem` 均已在 `.gitignore`（T21 落实），**任何时候不入仓**。
- 文件权限统一 `chmod 600`，属主为运行账号（如 `ruoyi`）。
- 泄露处置：商户平台可重置 APIv3 密钥与证书序列号；小程序 AppSecret 可重置；处置后同步更新部署机文件并重启后端。

## 6. 商家端部署


## 7. 小程序发布与合法域名

1. **合法域名配置**（微信公众平台 → 开发管理 → 开发设置 → 服务器域名）：
   - request 合法域名：`https://api.example.com`
   - uploadFile / downloadFile 合法域名：`https://api.example.com`
   - WebSocket 合法域名：`wss://api.example.com`
   - 域名必须 ICP 备案且 HTTPS，每月可修改次数有限，一次配好。
2. **微信支付关联**：小程序后台"支付管理"关联已绑定的商户号。
3. **发布流程**：HBuilderX 发行→微信小程序，或 `cli` 构建；本地 `manifest.json` 的 AppID 换成正式 AppID；体验版验收后再提交审核发布。
4. 小程序端无需任何支付开关配置——渠道由后端 `/api/pay/config` 与 `/api/pay/submit` 响应决定。

| # | 检查项 | 期望值 | 核对方式 |

| 10 | 定时任务 | `sys_job` 中超时关单/查单兜底/微信查单/退款查单四个任务 `status=0`（正常） | 管理后台"定时任务"页面 |

| 12 | HTTPS | 两域名证书有效、HTTP 自动跳 HTTPS | 浏览器/openssl |
| 13 | WebSocket | `wss://api.example.com/websocket/order?token=<若依token>` 能握手 | 商家端登录后收新单提醒实测 |

## 9. 日志与回滚

- 日志：`/home/ruoyi/logs/`（sys-* 与 error 级别分离，logback.xml 控制）；systemd 方式另有 `journalctl -u apos`。
- 回滚：保留最近 2~3 个 `ruoyi-admin.jar` 版本（`/opt/apos/releases/`），回滚 = 替换软链 + `systemctl restart apos`；数据库增量脚本向前执行，回滚需按脚本反向评估（上线前先备份：`mysqldump takeout > backup_$(date +%F).sql`）。
- 支付对账：出现回调丢失等异常时，依托 T24/T25 的查单兜底任务自动补偿；人工核对用 `biz_payment_record.transaction_id`、`biz_order_refund.refund_id` 与商户平台订单号互查。
